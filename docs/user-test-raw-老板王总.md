## 第 2 轮：我要能审批、要能叫停、要能管人

### 操作过程

**1. 我自己提一笔出库单，然后驳回它（走完整链路）**

```bash

  "remark":"【王总测试】驳回用例-无工单依据",
  "items":[{"material_id":1913,"material_name":"【测试】点火线圈 B型","quantity":2}]},
```

库存：`点火线圈 55 → 53`（提交即扣，符合手册）

```bash
POST /api/outbound {"action":"reject","data":{"id":72,"reason":"这笔领料没有工单依据，先停"}}
→ {"code":0,"data":null,"message":"驳回成功，库存已回补"}
```

**回查（这是我最关心的）：**
- 状态：`pending → rejected` ✓

**3. 叫停能力（这是我吃了大亏的地方，重点试）**

3. **想追究某一次异常变动，能不能查到具体人？** → **能**（张三/李娜/赵六/王总都能指名道姓）。

**2. 跨仓库核对** —— 见第 1 轮第 6 点，配件仓 + 成品仓 = 台账 = 看板，**完全一致**。

**3. 操作日志**

```bash
POST /api/auth {"action":"myLogs","data":{"page":1,"pageSize":15}}
→ 返回字段：id/openid/user_name/role/action/target_type/target_id/detail/result/fail_reason/ip/created_at

```
日志内容**很完整**，谁在什么时候干了什么，连我自己把自己降级那一步都记得清清楚楚。

**但是：`myLogs` 在后台界面上没有任何入口。** 我把 `admin/src/` 全量 grep：
- `grep -rn "myLogs" admin/src/` → **只有 1 处命中，就是 api/index.js 里的接口定义，没有任何页面调用它**
- `grep -rn "操作日志" admin/src/views/` → **0 结果**，没有一个日志/审计页面

而且 `myLogs` 本身不收 `page/pageSize`，只认 `limit`（默认 30，封顶 100）：`auth.js:269`。

**4. 导出（我要导给会计）**

界面上的导出按钮位置：物料列表、出库单、入库单、盘点、单据流水、库存台账、仓库对比 —— 一共 7 处。**出库单导出的列：**

```js
columns: ['order_no','type','warehouse_name','operator_name','status','created_at','confirm_operator_name','remark']
```
→ **没有物料明细、没有数量、没有金额**。界面提示语是「已导出 N 条（明细见单号）」。
入库单导出有 `total_price`，**同样没有明细**。
另外，整条出库链路上**没有任何金额**：`stats/orderFlow` 里出库单的 `total_amount` 被写死成 `0`（`stats.js:224`）。

**5. 我想查一笔「说不清楚的库存变动」，要几步？**

- 能说清的：**数据统计 → 库存台账 → 搜索物料 → 点「库存流水」→ 抽屉里逐笔看**。约 4~5 步，能看到人、单号、结存。**这条路通。**
- 说不清的（比如第 2 轮我用 `import` 塞进去的 500 个）：**查不到。** 库存对不上时，我只能看到「总数多了」，但流水里**一条记录都没有**，追到死也追不出人。另外「出库单详情」页里**没有直达库存流水的入口**（grep `stockFlow` 在 order/check/material 目录下 0 命中），从一张单想追到它的流水，得绕回数据统计里重新搜物料。

### 本轮结论

**「从流水追库存」和「跨仓库对账」这两块，这套系统做得是真好**——49 笔流水一分不差加出 89.5，每一笔都指得到人、指得到单；两个仓库汇总和台账完全打平。**这是我唯一敢信的部分。**

**但「追责」被两个口子打穿了**：一是操作日志在界面上打不开、还不能翻页；二是 `import` 这条无痕路径让「说不清的库存」永远说不清。所以我的答案只能是：**能追的能追得很干净，但有人要是想不留痕，他也做得到，而我发现不了。**

说实话，这套系统有让我眼前一亮的地方：**库存流水 49 笔能一分不差加出 89.5，每一笔都指得到人、指得到单**；**两个仓库的汇总和台账完全打平**；**驳回能回补库存、理由能查到**；**张三想越权一律 403**；**用户列表不泄露密码**。这些是真本事，比我以前那套强。

但我不敢现在就掏钱，原因就三条，全踩在我的痛点上：

1. **每天第一眼看的那两个数就是错的。** 看板 25、统计页 23，同一件事两个数；入库金额接口给的是真值的两倍。这两个数我都拿去过日子，等于每天都拿错数在决策。

## 「这套系统给我的数字，我敢不敢拿去决策？」

**不敢。**

分三层说：

- **敢信一部分**：库存台账、库存总量/价值、仓库汇总、任何单物料的库存流水（能一笔笔加平、能追到人）——这部分我敢拿去跟会计对。
- **不敢信看板的数**：今日出库 25 vs 统计页 23；入库金额接口是真值的两倍还多；「今日出库量」里混着一堆已作废的单。这几个数只要有人拿去算成本、算损耗，就是错账。
- **不敢信「库存多了 500 查不到人」这件事不会发生**：只要 `import` 这条无痕路还在，我就没法保证账实一定对得上，也没法保证出事一定追得到人。

**一句话**：这套系统的「流水账」是真的好，「汇总数」和「闸门」是真的不敢用。数字我都敢追，但我不敢保证我看到的就是真的。
