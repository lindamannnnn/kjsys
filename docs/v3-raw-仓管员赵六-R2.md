## 二、我报的问题

### [P1] 直接入库单可提交「单价 0」，且 0.001 会被静默取整为 0 —— 入库成本可被清零，与采购录入「单价必须 > 0」的口径自相矛盾

- **我做了什么（原始请求）**：
  ```json
  POST /api/inbound
  { "action": "submit", "data": {
      "warehouse_id": 1, "type": "purchase", "supplier": "【测试】R2-零价供应商",
      "remark": "[V3-R2] 单价填0",
      "items": [ { "material_id": 2103, "material_name": "【测试】机油滤芯 D型", "quantity": 1, "unit_price": 0 } ]
  }}
  ```
- **系统回了什么（原始响应）**：
  ```json
  { "code": 0, "data": { "_id": 586, "order_no": "IN-20261003-008", "total_price": 0 },
    "message": "入库单提交成功" }
  ```
  变体（单价填 `0.001`）：
  ```json
  // 请求 unit_price: 0.001 → 响应 code=0，order_no IN-20261003-011，total_price 0
  // detail 回读明细：items[0].unit_price = 0
  ```
- **我认为哪里不对 / 应该是什么样**：
  1. 采购入库的单价是**加权平均成本**的唯一来源，填 0 会把该物料的 `avg_cost` 直接拉向 0，账实、成本、利润全废。所以 `/api/purchase` 的采购录入环节明确写了「每一项的实际单价都必须大于 0」，填 0 会被拒。
  2. 但**同一个成本、走直接入库这条路却没有任何 > 0 的兜底**（`utils/validate.js` 的 `unitPrice` 只拦负数/非数字，源码注释也是「单价非负」）。两条入库路径口径不一致，等于「从侧门就能把成本清零」。
  3. 更隐蔽的是 `0.001`：输入 > 0 能过校验，却被 `toFixed(2)` **静默取整成 0**，单据上看不出异常，事后对账极难发现。
  4. 期望：直接入库的 `unit_price` 也应强制 **> 0**（或至少拒绝取整后为 0 的值），与采购录入保持一致；如果确实存在 0 成本入库的业务（如赠品），应走单独的类型并显式留痕，而不是让「0」混在普通采购入库里。
- **有没有证据**：**有证据**。见 `raw-sk-r2/B6-price-zero.json`、`raw-sk-r2/extra-price-tiny.json`、`raw-sk-r2/extra-price-tiny-detail.json`（detail 明确回读 `unit_price: 0`）。

> 备注：本问题是本轮 25 项错误尝试里**唯一漏掉的一项**（B6 与附1 同根因，合并为 1 条）。其余 23 项系统全部拦住或按预期给出幂等/正确提示。

## 三、系统做对的地方

1. **入库金额/数量校验很硬**：单价 -10、单价 "abc"、缺供应商、供应商空白串、数量 0 / -2 / 2.5，全部被 400 拦下，且提示是仓管看得懂的中文（带具体填入值）。
2. **一张单只允许一个仓库的物料**：混仓提交被明确拒绝「当前混了仓库 1、2，请分开提交」——这条对同时管两个仓的我尤其重要，否则库存会串仓。
3. **入库作废的库存保护**：B12 里货被领用后库存只剩 2，再作废需扣 5，系统拒绝并给出「当前库存 2，作废将需要扣减 5，请先处理相关出库单据」，避免了负库存。
4. **正常入库→作废能精确回退库存**：B11 库存 11→14→11，一分不差，说明「提交即加库存 / 作废即回退」是对称的。
5. **状态机不跳步**：pending 单直接 `pickDone`/`receive`、open 任务直接 `receive`、已确认入库单自行改价、已完成单重复 confirm，全部按当前状态给出准确提示（或幂等提示），没有出现「跳过确认直接扣库存」这类越级操作。
6. **盘点录入防护到位**：负数实盘、范围外物料、空 items 三连拒，且已提交待审的单不允许再改数（防止老板看到的和你交的不是同一份）。
7. **权限边界有效**：仓管调 `user.updateRole` 被 403 挡住；已确认入库单改价被挡回给老板/管理员。
8. **数据范围收敛正确**：我能同时看到配件仓和成品仓的单（本岗位设计如此），没有出现越界的第三个仓库数据。
