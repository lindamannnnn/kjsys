# 【采购员】李娜 · 3 轮真实使用汇报

## 使用前提

我是李娜，佛山厨具厂采购员，干这行 4 年。我每天在淘宝/京东下单、跑本地五金店，最关心三件事：**这单花了多少钱、有没有买错、仓管到底收没收货**。V2 之后我的活变成：仓管发布采购任务 → 我领取 → 我把「实际单价 + 购买方式 + 外部单号」录进去 → 等仓管收料入库。我不再能自己提交入库单。

- 账号：`lina`（角色 purchase，可管仓库 1、2）
- 测试期间只操作名称带「【测试】」的 7 个物料。

## 第 1 轮：正常作业——把手上这单采购干完

### 操作过程

**① 先看有几件事等着我**

```bash
curl -s -X POST http://127.0.0.1:3000/api/purchase -H "Authorization: Bearer <lina>" \
  -d '{"action":"myTodoCount","data":{}}'
```
→ `{"code":0,"data":{"can_take":1,"in_progress":1,"total":2},"message":"操作成功"}`
（1 张可领、1 张进行中。符合 context 留给我的 2 张。）

**② 看任务列表，其中 CG-20261003-002 待领取**

```bash
curl -s -X POST http://127.0.0.1:3000/api/purchase -H "Authorization: Bearer <lina>" \
  -d '{"action":"list","data":{"status":"open"}}'
```
→ 返回 `task_no:CG-20261003-002`，`status:open`「待领取」，明细 `【测试】刹车片 C型 × 15`，`can_take:true`。

**③ 领取**

```bash
-d '{"action":"take","data":{"id":2}}'
```
→ `{"code":0,"data":{"status":"taken"},"message":"领取成功，请尽快采购并录入"}`
detail 显示 `taker_name:"李娜"`、`status_text:"采购中"`。

**④ 采购录入（购买方式=淘宝，外部单号，逐项填实际单价 12.5）**

```bash
-d '{"action":"entry","data":{"id":2,"purchase_channel":"淘宝","external_no":"TB-LINA-0001",
     "remark":"李娜采购录入","items":[{"material_id":2102,"unit_price":12.5}]}}'
```
→ `{"code":0,"data":{"status":"purchased"},"message":"已提交，等待仓管收货入库"}`
detail 显示 `total_amount:187.5`（=15×12.5）、`purchase_channel:"淘宝"`、`external_no:"TB-LINA-0001"`、`status_text:"待收料"`。
**这一轮核心流程：领取 → 录入 → 待收料，顺畅，金额算对了。**

**⑤ 看自己领的任务与未读消息**

- 任务列表可见 3 条与我相关：CG-001（已入库）、CG-002（我领的）、CG-003（我领的）。
- 未读消息：`{"code":0,"data":{"unread":0}}`，消息列表全空（当时以为正常，第 2 轮才知有问题）。

### 遇到的问题

| 序 | 问题 | 严重度 | 证据（请求→响应） | 为什么干不下去 |
|---|---|---|---|---|
| 1-1 | 「指定采购员」下拉里没有真实员工，只有两个开发账号 | P2 | `purchase.assignees` → `{"list":[{"openid":"dev_worker_01","name":"开发·全能"},{"openid":"dev_purchase","name":"开发·采购"}]}`；而 `auth.getUserInfo` 显示我 `openid:null` | 仓管想在后台「指定李娜采购」是选不到我的。不影响我领公开任务，故不算卡死 |

### 本轮结论

正常作业能一口气走完：领任务 → 录单价 → 待收料，金额与状态都对。唯一的别扭是「指定采购员」形同虚设。

## 第 2 轮：做错事与异常——我故意乱填，看系统拦不拦

为了让「采购中」状态的任务可以被反复试，我先让仓管（赵六）把我那张任务退回（这正是「被退回后重填」的场景），然后逐条乱填。**注意：只要一条非法输入被系统放行，任务就变成「待收料」，后续测试会被状态挡住，所以我每条都先退回一次再试。**

### 操作过程与原始证据

**㈠ 退回 + 退回后数据残留**

```bash
# 仓管退回 CG-002
{"action":"rejectBack","data":{"id":2,"reason":"单价与市场价不符，请重填"}}
```
→ `{"code":0,"data":{"status":"taken"},"message":"已退回采购员，请他补充后重新提交"}`
退回后我立刻 `detail`：

```json
{"status":"taken","status_text":"采购中","purchase_channel":"淘宝",
 "external_no":"TB-LINA-0001","total_amount":187.5,
 "items":[{"material_id":2102,"quantity":15,"unit_price":12.5}],
 "reject_reason":"单价与市场价不符，请重填"}
```
→ 任务已是「采购中」，但上一轮填的**购买方式、外部单号、单价、金额全都还在**。

**㈡ 逐条异常输入（每条先退回一次）**

| 试什么 | 请求 data 关键段 | 系统响应 | 我的判断 |
|---|---|---|---|
| **a. 不给单价** | `"items":[{"material_id":2102}]` | `{"code":0,"data":{"status":"purchased"},"message":"已提交，等待仓管收货入库"}` | **放行了！** 提交后 `total_amount:0`、`unit_price:0` |
| **b. 单价填 0** | `"items":[{"material_id":2102,"unit_price":0}]` | `{"code":0,"data":{"status":"purchased"}}` | **放行了！** 金额 0 |
| **c. 单价填 -5** | `"unit_price":-5` | `{"code":400,"message":"单价不能为负数"}` | 拦住了，提示清楚 |
| **d. 购买方式=拼多多** | `"purchase_channel":"拼多多"` | `{"code":400,"message":"购买方式只能是：淘宝 / 京东 / 线下 / 其他"}` | 拦住了，提示清楚 |
| **e. 不填购买方式** | 无 `purchase_channel` | `{"code":400,"message":"请选择购买方式"}` | 拦住了，清楚 |
| **f. 单价填 "abc"** | `"unit_price":"abc"` | `{"code":0,"data":{"status":"purchased"}}` | **放行了！** 非数字被静默当 0，金额 0 |
| **g. 明细给空数组** | `"items":[]` | `{"code":400,"message":"请填写「【测试】刹车片 C型」的实际单价"}` | 拦住了，且点名是哪项 |

**㈢ 其它异常**

| 试什么 | 请求 | 响应 | 判断 |
|---|---|---|---|
| 已提交后再改 | 对已 `purchased` 的任务再 `entry`（改京东/单价99） | `{"code":400,"message":"该任务已提交采购信息，等待仓管收料，请勿重复录入"}` | 拦住了，合理 |
| 重复领取（我已领的） | `take id=2` | `{"code":0,"data":{"duplicated":true},"message":"你已经领取过这项任务，请继续采购录入"}` | 友好；但对「已录入」任务提示「请继续采购录入」措辞略不准 |
| 领取已完成 | `take id=1`（received） | `{"code":400,"message":"该任务当前状态「已入库」，不能领取"}` | 拦住了，清楚 |
| 领取别人领走的 | 王总先领走 id=5，我再 `take id=5` | `{"code":400,"message":"该任务当前状态「采购中」，不能领取"}` | 拦住了；但**没告诉我被谁领走** |
| 看别人任务的详情 | `detail` 王总领的任务 | `{"code":403,"message":"只能查看自己领取的、或面向你开放的采购任务"}` | 拦住了，好 |
| 并发抢单 | 我与王总**同时** `take id=7` | 我：`{"code":0,...,"领取成功"}`；王总：`{"code":400,"message":"该任务当前状态「采购中」，不能领取"}`；最终 taker=李娜 | **并发只有一个成功，符合手册承诺** |

**㈣ 消息通知（重点存疑）**

仓管退回我 → 我看 `message`：`{"code":0,"data":{"list":[],"total":0,"unread":0}}`（空）。
仓管发布新任务（提示「已通知采购员」）→ 我再查：仍 `unread:0`、列表空。
我提交录入（提示「等待仓管收货入库」）→ 用仓管 token 查，仓管也未读数 = 0、列表空。

### 遇到的问题

| 序 | 问题 | 严重度 | 证据（请求→响应） | 为什么干不下去 |
|---|---|---|---|---|
| 2-1 | **采购单价不校验「必填且>0」**：漏填 / 填 0 / 填非数字（"abc"）都能提交成功，金额算成 0 | **P0** | 见上表 a/b/f：三种输入都 `code:0 status:purchased`，`total_amount:0` | 我手一滑漏填单价，这单入库成本就是 **0 元**，账是错的，而且系统照样提示「已提交」。月底对不上账 |
| 2-2 | 退回后旧采购信息不清空，列表「实际金额」列在「采购中」状态下仍显示上次金额 | P2 | 见㈠：`status:taken` 却 `total_amount:187.5` | 后台「实际金额」会显示 ¥187.50 而状态是「采购中」，仓管容易误判我已经录好了。可理解为「方便重填」，但需明确 |
| 2-3 | 退回/发布/录入都收不到任何站内消息 | P1 | 前后四次查 `message` 均为空；但提示语写「已通知采购员」 | 我不主动刷任务列表，就不知道任务被退回、也不知道有新任务。靠「猜」上班 |
| 2-4 | 领取失败只报状态，不报「被谁领走」 | P2 | `{"code":400,"message":"该任务当前状态「采购中」，不能领取"}` | 我以为自己手慢了，其实得回去翻列表才知道是谁 |

### 本轮结论

**拦住的部分**（负数、非法购买方式、缺购买方式、空明细、重复改、越权看、并发抢单）做得不错，提示语都说人话。
**没拦住的部分要命**：单价漏填、填 0、填字母全部放行，直接产出一张成本 0 元的入库单——这是采购岗最不能出的错。

## 后台与小程序一致性

### ① 后台到底有没有「采购任务」这个功能页面？——**有，而且挺全**

`admin/src/views/purchase/tasks.vue` 是完整的采购任务页，路由 `order/purchase-tasks`（`admin/src/router/index.js:105-110`，注释写明「仓管发布 → 采购员领取并录实际单价 → 仓管收料入库」）。它能：
- **发布任务**（`submitCreate`，可选目标仓库 + 指定采购员 + 物料明细 + 备注）；
- **看详情**（`openDetail`，弹窗含**实际单价、实际总额、购买方式、外部单号、退回原因、入库单号**）；
- 领取、采购录入、收料入库、退回、取消都在同一页。

出库页也同步了 V2 四阶段：`admin/src/views/order/outbound.vue:11-12` 有「待拣货 / 待收货」筛选项，`:227-228` 有对应状态文案，`:259-266` 说明这三态可驳回。**这一条后台与小程序是同步的，没有再犯「后台还停在老流程」的毛病。**

### ② 后台有没有「消息中心」？——**没有页面**

`admin/src/api/index.js:216-221` 定义了 `messageApi`（含 `unreadCount`、`markAllRead`），但**全项目没有任何 `.vue` 使用它**（`grep messageApi *.vue` 无结果），router 里也没有消息路由。也就是说后台有接口、没入口。小程序侧是有的（`miniprogram/src/pages/message/list.vue`）。
→ **归类：后台与小程序不同步（后台缺消息中心页面）。**

### ③ 管理员看到的数据 vs 我看到的，一样吗？——**逐字段一致**

用 `admin/123456` 登录取 token，查我处理过的任务：

| 任务号 | 我（李娜）看到 | 管理员看到 | 是否一致 |
|---|---|---|---|
| CG-20261003-002 | 已入库 / 线下 / 187.5 / (2102,15,12.5) | 已入库 / 线下 / 187.5 / (2102,15,12.5) | ✅ |
| CG-20261003-003 | 已入库 / 淘宝 / 470 / (2105,20,23.5) | 已入库 / 淘宝 / 470 / (2105,20,23.5) | ✅ |
| CG-20261003-001 | 已入库 / 线下 / 1026 | 已入库 / 线下 / 1026 | ✅ |
| 入库单 IN-20261003-004 | 187.5，库存 18 | 同一入库单 `total_price:187.5` | ✅ |

**状态、单价、金额三样全对得上，后台没有独立口径。**

### ④ 顺带查到：后台的采购录入同样允许单价填 0

`tasks.vue:262` 用 `<el-input-number v-model="row.unit_price" :min="0" ...>`，`:min=0` 意味着**后台也放行 0 单价**，和我在小程序端遇到的是同一个洞（服务端 `server/src/modules/purchase.js:443-445` 也只判 `p < 0`）。
→ 说明第 2 轮那个 P0 是**前后端一致的缺陷**，不是小程序独有。

### ⑤ 消息为什么一条都收不到（附带发现，含推测）

`server/src/services/message.js:37-47` 投递时按 `openid` 展开收件人，且 `WHERE openid IS NOT NULL AND openid <> ''`。`admin user.list` 显示四个测试岗位账号 `lina / zhaoliu / wangzong / zhangshan` 的 **openid 全为空**，只有 `dev_*` 开发账号有 openid。

证据：
```
admin user.list →
 lina      roles=['purchase']    openid=None
 zhaoliu   roles=['storekeeper'] openid=None
 dev_purchase roles=['purchase'] openid='dev_purchase'
```
推理：收件人集合为空 → `pushMessage` 直接返回 0 → 不写任何消息行。所以**在这套测试账号下消息中心必然是空的**；提示语「已通知采购员」在此时是假话。**（真实小程序用户有 openid 时消息应能正常投递——这一点为推测，未取到 dev 账号 token 验证。）**

## 严重问题汇总

### P0 致命（不修我没法用）
1. **采购录入不校验单价「必填且 > 0」**——漏填、填 `0`、填非数字（`"abc"`）三种情况**都提交成功**，系统把金额算成 **0 元**并生成一张成本为 0 的入库单。
   - 证据：`entry` 不带 `unit_price` → `{"code":0,"data":{"status":"purchased"},"message":"已提交，等待仓管收货入库"}`，随后 `total_amount:0`。
   - 根因（读码确认）：`server/src/modules/purchase.js:443-445` 只有 `if (p < 0) return fail('单价不能为负数')`，`num()` 把缺失/非数字吞成 0；前端 `tasks.vue:262` 的 `el-input-number :min="0"` 也放行 0。
   - 影响：采购金额可被静默记成 0，入库成本、库存总值全跟着错，且仓管收料时不会二次校验。

### P1 严重（很影响效率）
1. **`stats.orderFlow`、`stats.stockFlow` 对采购员开放**，越权可见全公司单据流水与库存变动（含其他仓库、他人金额/操作人），与手册声明的权限不符。
2. **消息中心完全收不到通知**（测试账号 openid 为空 + 后台无消息中心页面）：任务被退回、有新任务、录入完成，我全得靠主动刷列表才知道；提示语「已通知采购员」不符实。

### P2 体验（能用但别扭）
1. 退回后旧采购信息（购买方式/外部单号/单价/金额）不清空，后台「实际金额」列在「采购中」状态下仍显示上次金额，易误判。
2. `purchase.assignees` 只列开发账号，真实采购员（我）不在「指定采购员」下拉里。
3. 领取失败只报状态，不提示被谁领走。
4. 字段命名不统一：入库单 `total_price` vs 采购任务 `total_amount`；`inbound.list` 表头不含金额字段，对账易读错。

## 我这个岗位愿不愿意继续用？

**愿意用，但那个 P0 不修我不敢真用。**

好的地方很明显：V2 的采购流程（领取→录单价→等收料）比老版清楚，状态一目了然；负数、非法购买方式、缺购买方式、空明细、重复改、越权、并发抢单这些该拦的都拦得干净，提示语也说人话；对账我逐笔算过，金额、加权成本、库存增减**全对**；后台还真的有采购任务页，和我小程序里看到的数值一字不差。

但那一条 P0 太要命——采购这行，单价是我唯一要签字确认的东西，系统却允许我漏填、填 0、填字母都「提交成功」，把成本记成 0。这不是「别扭」，是**直接做错账**。什么时候服务端加了「单价必须 > 0」的硬校验（后台输入框也别再给 `:min=0`），我就能放心用了。
