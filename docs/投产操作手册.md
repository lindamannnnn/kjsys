# 投产操作手册（正式启用当天照着做）

> 给谁看：你自己 + 厂长。
> 什么时候用：域名、微信登录、企微都配好之后，正式启用那一天。
> 按顺序做，每步做完打个勾。

---

## 第一步 · 启用前确认（先别清数据）

- [ ] 浏览器打开 `https://sl.ekkosys.cn/admin/` 能打开后台登录页
- [ ] 手机上小程序能打开（微信开发者工具或体验版）
- [ ] WX_SECRET 已填进生产 `.env`（微信登录能用）
- [ ] 企微三样已填进生产 `.env`（要推送的话）
- [ ] **先盘点**：把配件仓、成品仓的实物数量点数点清楚，记下来

### 🔒 安全基线（2026-10-16 已设好；换机器或重建环境时照做）

| 项 | 值 | 为什么 |
|---|---|---|
| `HOST` | `127.0.0.1` | 后端只监听本机，公网只能走 Nginx（HTTPS）。不设这条，`http://服务器IP:3000` 会被公网明文直连，绕过 TLS |
| `ALLOW_DEV_LOGIN` | `false` | 关掉「用 dev 身份直接登录」。生产必须 false，否则任何人可白拿任意角色身份 |
| 管理员密码 | 不入库、不进文档 | 仓库是 **public**。忘了密码用 `node src/db/reset-admin.js <新密码>` 重置（直接改库，不需要登录）|

自检命令（在生产上跑）：

```bash
# 应显示 127.0.0.1:3000，不是 0.0.0.0:3000
sudo ss -lntp | grep :3000
# 应返回 400 而不是登录成功
curl -s -X POST http://127.0.0.1:3000/api/auth -H 'Content-Type: application/json' \
  -d '{"action":"login","data":{"dev_openid":"dev_boss"}}'
```

## 第二步 · 数据清 0（清掉试用期的数据）

⚠️ 这一步会把试用期的单据、流水、库存数字都清掉，物料档案和员工账号保留。**先确认你已经盘点完、记好实盘数**。

```bash
# 在生产服务器上跑（SSH 上去）
cd /opt/shenglong/server
node src/db/reset-production.js          # 先看预览：会清什么、留什么
node src/db/reset-production.js --yes    # 确认后执行（会要你输入「确认清0」，并自动备份）
```

清完：库存全 0、单据全空、测试账号删掉，物料档案和真实员工账号还在。

---

## 第三步 · 录期初库存（把实盘数录进去）

1. 用 Excel 打开 `期初库存导入模板.csv`（里面已经预填了所有物料）。
2. 对照盘点结果，填两列：**实盘数量**、**期初单价**（单价不填就按 0，以后真实采购入库会自动更新）。
3. 没货的料数量填 0 或留空（会跳过）。
4. 另存为 CSV，然后跑：

```bash
cd /opt/shenglong/server
node scripts/init-stock.js 期初库存导入模板.csv --dry-run   # 先演练：看匹配对不对，不写库
node scripts/init-stock.js 期初库存导入模板.csv            # 确认无误后正式建账
```

✅ 跑完：每个仓生成一张「期初建账」入库单，库存就按实盘进来了，库存流水里有记录（责任人=管理员）。

---

## 第四步 · 员工账号和角色

在后台 `https://sl.ekkosys.cn/admin/`（用管理员账号登录）：

- [ ] 「用户管理」里给每个员工建账号 / 核对已有账号
- [ ] 给每人**分配角色**（领料员 / 采购员 / 仓管 / 厂长 / 老板）
- [ ] 仓管、厂长这类要收通知的，**填上「企微账号」**（企业微信里的成员账号）
- [ ] 仓管要选好「可操作仓库」（配件仓管只管配件仓、成品仓管只管成品仓）

### ⚠️ 账号有两种来源，别搞混（2026-10-16 补充）

| 来源 | 有 openid？ | 能不能收通知 |
|---|---|---|
| 员工**自己用微信登录小程序**自动建的账号 | ✅ 有 | ✅ 站内信 + 企微 都能收到 |
| 管理员在后台「新增用户」手工建的账号（账号+密码） | ❌ 没有 | ⚠️ 只有**填了企微账号**才能收到企微；站内信看不到 |

**推荐做法**：让员工**先自己用微信扫码进一次小程序**（这样系统里就有了他的微信身份），
你再在后台给**那条记录**分配角色、填企微账号。这样一个人只有一个身份，权限配一次就够。

如果你是在后台手工建账号（给仓管/厂长登录网页后台用），那要注意：
**同一个人会变成两条记录** —— 小程序那条管通知，后台那条管网页操作，
**角色要在两条上都配一遍**（这是当前设计的限制，不是 bug；后续可以做成「两条身份合并」，需要时告诉我）。

## 数据备份与恢复（2026-10-16 建立）

### 自动备份

生产数据库**每天 03:40 自动备份**一次，文件放在服务器的 `/var/backups/shenglong-mysql/`，
形如 `shenglong-20261016-111525.sql.gz`，**保留最近 30 天**，超期自动清理。

```bash
# 看定时器下次什么时候跑
systemctl list-timers shenglong-mysql-backup.timer

# 看最近一次备份的日志
journalctl -u shenglong-mysql-backup.service -n 20

# 看现有备份
ls -lh /var/backups/shenglong-mysql/
```

### 手动备份一次（改数据前建议先跑）

```bash
sudo /opt/shenglong/backup-mysql.sh
# 或在 server/ 目录下：npm run backup
```

脚本会给三重校验（文件大小 / 能否解压 / 有没有建表语句），**不合适就报错退出，不会留下坏文件**。

### 恢复演练（建议每月跑一次，确认备份真能用）

```bash
sudo bash /opt/shenglong/server/tests/restore-drill.sh
# 或在 server/ 目录下：npm run restore:drill
```

它会把最新备份导进一个临时库（`shenglong_restore_probe`），对比表数和关键表行数，
**验证完自动删掉临时库**，不碰生产库。最后一行显示 `✅ 恢复演练通过` 就说明备份是好的。

### 万一真要恢复（出事了才用）

```bash
# ⚠️ 会覆盖当前数据，执行前先确认这是你要的备份文件
gunzip -c /var/backups/shenglong-mysql/shenglong-20261016-111525.sql.gz | sudo mysql shenglong
```

### 异地备份（备份同步到你的电脑）

服务器上的备份万一跟着服务器一起挂掉就没了，所以**每天还会自动同步一份到你这台电脑**：

- 存放位置：**`G:\sl\backups\`**
- 同步任务：Windows 计划任务 **`ShengLong-BackupPull`**，每天 **04:10** 跑（服务器 03:40 备份完之后）
  - 电脑当天没开机也没关系：任务设了「错过后尽快补跑」，下次开机自动补
  - 同步范围是服务器上全部 30 天内的备份（每个约 90KB，不占空间）
- 本机保留 **60 天**，更早的自动清理
- 看同步记录：`G:\sl\backups\pull-backups.log`
- 手动同步一次（想立刻拉）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "G:\sl\tools\pull-backups.ps1"
```

> 脚本已随仓库保管：`server/deploy/pull-backups.ps1`（换电脑时照它重建计划任务即可）。
>
> 顺带说明：服务器上原来那个「每日自动备份」（`shenglong-backup.timer`）备份的是
> **上一代系统的 SQLite 文件**（`/home/ubuntu/lingliao/data.db`），跟现在这套系统**没有关系** ——
> 也就是说本项目在 2026-10-16 之前**一直没有自动备份**，这一节是补上来的。
> 那三个旧服务（含一个每 6 小时报一次错的同步任务）已于同日**停用并禁用**，8899 端口已释放。

## 常见问题

| 情况 | 怎么办 |
|---|---|
| 员工扫进来没看到功能 | 后台还没给他分配角色，去「用户管理」分配 |
| 企微收不到通知 | ① 生产 `.env` 的企微三样配了吗 ② 这个人的**企微账号**填了吗 ③ 企微后台「企业可信IP」加了 `119.91.206.235` 吗。自测：`node scripts/test-wecom.js 某人的企微账号` |
| 后台建的账号收不到通知 | 站内信按小程序身份投递，后台账号没有微信身份 → 至少要**填企微账号**才会收到企微推送 |
| 小程序提示网络异常 | 检查手机是否连网；确认小程序后台「服务器域名」配了 `https://sl.ekkosys.cn` |
| 库存数字不对 | 看「库存流水」——每笔出入库都有记录和责任人 |
