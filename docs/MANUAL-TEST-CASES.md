## 0. 测试前准备

### 0.1 把环境跑起来

```bash
npm run server      # 后端 3000
npm run admin       # Web 后台 5173
npm run build:mp    # 编译小程序（改过代码后必做）
npm run mp          # 打开微信开发者工具
```

手机跑：**开发者工具 → 真机调试 → 扫二维码**（不要用「预览」，会被域名白名单拦成白屏）。
详细排错见 `docs/MP-TEST-GUIDE.md`。

### 0.2 七个测试身份（切身份：「我的」→ 最下面「开发身份」）

| 身份 | 角色 | 可见仓库 | 能做什么 |
|---|---|---|---|
| 开发·全能 | out,in,storekeeper,purchase | 仓1+仓2 | 出/入库、确认单据、改价、采购 |
| 开发·出库员 | out | 仓1 | 只能出库，只看自己提交的单 |
| 开发·入库员 | in | 仓1 | 只能入库、改价 |
| 开发·仓管 | storekeeper | 仓1 | 确认/驳回单据、建盘点单、录入盘点 |
| 开发·采购 | purchase | 仓1 | 采购入库、能看全部出库单、对账流水 |
| 开发·老板 | boss | 仓1+仓2 | 看板/趋势/预警、**审核盘点**、看全部单据 |
| admin（Web后台） | admin,boss | 全部 | 一切 + 用户管理、物料管理、强制改密口子已关 |

> ⚠️ **两个坑，先记住，不然会以为测出 bug：**
> 1. **「全能」并不全能**：它没有 `boss` 角色，所以**看不了趋势分析、审核不了盘点**。这两处必须切「开发·老板」。
> 2. **「开发·出库员」只能看到自己提交的单**，别人提交的单他看不到——这是设计如此，不是 bug。

### 0.3 数据前提（必须先做）

- 全部 1906 条物料库存都是 **0**，所以**顺序必须是：先入库 → 再出库**。
- 统一用这条物料做主测试：**编号 `A001-7`，冷板 0.8\*1000\*1460，配件仓，单位「个」**。
- **供应商表目前 0 条**，采购测试会用到「新建供应商」（见 §6）。
- 想看预期是否正确，随时去后台核对：`http://localhost:5173` → 配件仓物料 → 搜 `A001-7`。

| 录入盘点 | ❌ | ❌ | ❌ | ✅ | ✅ | ✅ |

## 11. 端到端一条龙（建议第一次先跑这个，约 20 分钟）

按这个顺序，**每一步都对得上才算业务闭环**：

1. **入库员**：入库 A001-7 × 100 @3.5 → 库存 100，成本 3.50 ✅
2. **入库员**：再入库 × 50 @4 → 库存 150，成本 **3.6667** ✅
3. **出库员**：出库 30 → 库存 **120**（立刻扣，不用等确认）✅
4. **仓管**：待确认 → 看到该单 → 确认 → 库存**仍是 120** ✅
5. **出库员**：**换一条物料**（如 A001-8，先给它入 50 个）→ 提交出库 20 → 10 分钟内撤销 → 库存回补到 50 ✅
6. **仓管**：把上面那张再提交一次并驳回（必填理由）→ 库存回补；**出库员首页出现红条提醒** ✅
   > 这两步刻意**不用 A001-7**，否则会把它的库存搅乱，第 7 步的账面数就对不上了
7. **仓管**：建盘点单（勾 A001-7 / A001-8，不要全盘）→ A001-7 录实盘 `118` → 进入「待审核」✅
8. **老板**：审核通过 → A001-7 库存 **118**；流水多一条「盘点差异调整：账 120 → 实 118」✅
9. **老板**：看板/趋势/预警有数 ✅
10. **后台**：配件仓搜 A001-7，库存 = 118，与小程序的数**完全一致** ✅

## 12. ⚠️ 测之前先看：设计 vs 实际实现的 12 处差异

**这些不是 bug，是代码就这么实现的。** 免得测到一半怀疑人生：

| # | 设计文档写的 | 实际代码实现 |
|---|---|---|
| 1 | 审批通过后才扣库存 | **提交那一刻就改库存**，仓管确认只改状态 |
| 2 | 云开发 + MongoDB | 自建 Node + Express + MySQL（部署时才知道的区别） |
| 3 | 确认/审批写操作日志+流水 | **确认动作不写库存流水**（只在库存真变时写） |
| 4 | 出库/入库都要审批 | 二者都先落 `pending`，确认只是事后复核 |
| 5 | 盘点有「驳回」 | 只有「**退回**」（→盘点中待重盘）和「作废」，都不动库存 |
| 6 | 「盘点中」= 录入中 | 「盘点中」= **被老板退回后等待重盘** |
| 7 | 入库单可被驳回 | **入库单没有驳回**，只有作废 |
| 8 | 仓库权限未配置 = 无权限 | `warehouse_ids` 为空 = **不限制（看得见全部仓库）** |
| 9 | boss 与 admin 同级 | **admin 是隐形超管**（任何动作都放行）；boss 必须显式授权 |
| 10 | 入库作废会回算成本 | 入库作废**不回算** avg_cost，只有入库和改价会改成本 |
| 11 | 期初建账 `init` 流水 | 代码中未实现（1906 条库存都是 0 的根因） |
| 12 | 小程序 15 个页面 | 实际 25 页（多了采购、仓管工作台、库存流水等） |
