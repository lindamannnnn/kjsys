二、本轮修复的 3 个真实缺陷 FIXED

这三个都不是「看代码猜的」，是在生产上真操作时当场报错、并有堆栈/接口回包为证。修复后都用同一个请求复验过。

P0 · 功能完全不可用

1. 采购员录采购单价 —— 100% 报错，采购线后半段全废

现象
采购员在「采购任务」里录入单价、购买方式 → 页面转圈后报错，任务卡在「采购中」走不下去
铁证
Unknown column 'channel_remark' in 'field list'（生产后端日志带堆栈）
根因
生产库 purchase_task_items 缺这一列；而"库结构对照文件"里也缺 —— 两边都缺，所以自动校验反而报「无异常」。这是漂移检测本身的盲区
修法
生产库补列 + 同步对照文件；另外新增一套「代码 ↔ 库」的列引用比对，堵住这个盲区
复验
✅ 同一请求修复前 500 → 修复后成功，采购链路一路跑到入库
P1 · 功能静默失效

2. 消息「已读」必然失败 —— 后台建的账号看不到自己的消息

现象
后台建的账号（仓管、采购、老板…）消息列表空白、未读数永远 0、点「全部标为已读」报「请先登录」
铁证
同库同代码，只换身份对照：赵六（后台建）列表空 / 未读数 0 / 标记已读 401；文彬（微信登录）列表 3 条 / 未读 3 / 标记成功
根因
发消息和读消息用了两套身份口径：发的时候用「微信号，没有就用账号名」兜底；读的时候只认微信号 —— 后台账号没有微信号，所以消息发得出去、收不到
修法
读的一侧统一成同一套兜底口径（这是全局唯一一处漏用，其余模块早已统一）
复验
✅ 赵六消息列表从空 → 3 条，未读数 3，标记已读成功
P1 · 功能静默失效

3. 采购员指派下拉框 —— 永远是空的

现象
仓管发采购任务时想指定采购员，下拉框一个选项都没有
根因
取人员的 SQL 主动排除了没有微信号的账号，而真实的采购员正是后台建的账号 → 被自己排除掉了
修法
去掉这个排除条件，改用统一的身份口径
复验
✅ 下拉框从空 → 正常出现「李娜」

顺带发现：原来的自动校验有个盲区，已补上

原先的库结构校验是「生产库 ↔ 本地对照文件」比对。但如果本地对照文件本身也忘了写这一列，两边都缺就会报「一切正常」—— 采购录价那个 P0 就是这么溜过去的。现已新增「真代码里用到的列 ↔ 数据库实际有的列」比对， 跑完只报出 1 处真缺失（已修），没有误报。以后这类问题部署后会自动现形。

五、需要你决定的 3 项轻微问题 NON-BLOCKING

都不影响上线，也不影响正常使用，但既然查出来了就如实列给你。

△ 1. 首页「消息」入口在首屏之外，未读红点要点进来往下滑才看得到

实测位置：消息入口在页面纵向 789px 处，而首屏可视高度只有 752px —— 正好差一点。 功能没坏，能滑到，但「有未读消息」这个提示用户第一眼看不到。 可选处理：把消息移到顶部、或缩短卡片高度、或不改（员工知道往下滑）。

△ 2. 小程序没有页面级的「按岗位拦住页面」

首页入口是按岗位精确隔离的（该岗位完全看不到不该有的入口），这点没问题。 但如果绕开首页直接打开某个页面（例如采购员打开仓管工作台），页面壳会打开、操作按钮也渲染出来， 只是数据被后端挡住（显示 0）、点按钮才报无权限。 不是数据泄露（后端拦得很死），是观感问题。要不要加一层页面守卫，你定。

△ 3. 个别接口对无权限角色返回「空列表」而不是「无权限」

例如领料员调采购任务列表 / 盘点列表，返回的是 200 + 空列表（因为按身份过滤后本来就没有他的数据）， 而不是 403。结果上没有任何数据泄露，只是口径偏松。可改可不改。
