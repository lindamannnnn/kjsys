# 小程序端测试流程

> 更新时间：2026-09-30　本机局域网 IP：**192.168.10.7**（换 WiFi 会变，查法见附录）
>
> **先明确一件事**：这套系统设计里**只有一个二维码**——就是进小程序用的那个。
> 员工拿微信扫它 → 打开小程序 → 在里面选料、填数、提交。
> **物料本身是不贴码的**，选料靠「搜索 / 分类 / 编号输入」。
> （设计原文 `analysis.md`：「员工不需要装任何软件，微信扫码就能用」；`docs/tasks.md`：「员工扫码进入小程序」）

## 零、开测前确认这四件事

| # | 事项 | 现在的状态 | 卡住的话怎么办 |
|---|---|---|---|
| 1 | 后端在跑 | 已监听 `0.0.0.0:3000`，局域网可达已验证 | 根目录 `npm run server` |
| 2 | 接口地址是局域网 IP | 已改成 `192.168.10.7` | 见第一节第 2 步，改完要重新编译 |
| 3 | 手机和电脑同一个 WiFi | 需自己确认 | 手机连家里/公司同一个 WiFi，不能走流量 |
| 4 | 物料库存是 0 | 1906 条库存全是 0 | **先入库再出库**，顺序不能反（见第三节） |

> 第 4 条是最容易踩的：不先入库，领料出库会直接提示「该物料缺货」，加不进清单。
> 这不是 bug，是本来就该这样——没进过货的东西当然不能领。

## 一、拿到那个二维码，扫码进小程序

### 开发阶段（现在用的方式）

微信开发者工具右上角 → **真机调试** → 屏幕上出现一个二维码 → **用手机微信扫它**。

这一个码就是全部的「扫码」入口。

> ⚠️ **不要用「预览」**：预览模式微信会严格执行域名白名单，
> 你这是 `http://192.168.10.7:3000` 这种临时地址，请求会被直接拦掉，
> 表现是「页面能打开、数据全是空的」或者一直转圈。
> 真机调试会开通调试通道、放行这类地址，才能真的连上你电脑上的后端。

### 正式上线后（这才是设计里那张「贴墙上」的码）

小程序发布后，微信公众平台 → 管理 → **小程序码** → 下载。
打印出来贴墙上，员工扫它进。届时 `cloud.js` 里的地址要换成 `https://你的已备案域名`。

### 前置：改地址并重新编译（做一次即可）

打开 `miniprogram/src/utils/cloud.js` 第 20 行，确认是局域网 IP：

```js
const API_BASE = 'http://192.168.10.7:3000'
```

> ⚠️ 写成 `localhost` 手机一定连不通——手机上的 localhost 指的是手机自己。

改完执行：

```bash
npm run build:mp     # 然后开发者工具里点「编译」
```

### 登录与切身份

开发模式已跳过微信授权，打开即登录（用的是开发身份）。
要换岗位 → 「我的」→ 最下面 **开发身份（切角色看不同界面）** → 点选，切完自动重登。

> 上线前要把 `cloud.js` 里的 `DEV_MODE` 改回 `false`，这块会自己消失。

## 二、六个测试身份（切了才能测权限）

| 身份 | 能看到 / 能做什么 | 用来测什么 |
|---|---|---|
| 开发·全能 | 出库+入库+仓管+采购，两个仓都能看 | 一个人跑完所有流程，最省事 |
| 开发·出库员 | 只能出库，只看**配件仓** | 仓库隔离：成品仓的料应该看不到 |
| 开发·入库员 | 只能入库，配件仓 | 入库单、单价、供应商 |
| 开发·仓管 | 待确认单据、确认/驳回 | 仓管环节 |
| 开发·采购 | 采购入库，配件仓 | 采购流程 |
| 开发·老板 | 看板、趋势、台账、预警，两仓 | 数据是否算对 |

## 三、主流程测试（按这个顺序才能走通）

> 每一步写清：点哪 → 输什么 → **应该看到什么**。

### 第 1 步：先把库建起来（入库登记）

首页 → **入库登记**

| 操作 | 期望结果 |
|---|---|
| 进页面 | 顶部出现仓库切换条（配件仓 / 成品仓），默认停在配件仓 |
| 搜索框输入 `A001-7` | 列表只剩 **1 条**：冷板 0.8\*1000\*1460 |
| 点这一条选中 | 下方出现「数量 / 单价 / 供应商」填写区 |
| 数量填 `100`，单价填 `3.5` | 小计自动算出 350 |
| 点 **提交入库** | 提示成功，列表清空 |

✅ **立刻验证**：`A001-7` 库存从 0 变 100。
后台 `http://localhost:5173` → 配件仓物料 → 搜 A001-7，能看到当前库存 100、成本价 3.50。

> 建议这一步**给 2~3 条物料各入一批**，后面出库、盘点才走得顺。

### 第 2 步：领料出库

首页 → **领料出库**

| 操作 | 期望结果 |
|---|---|
| 搜索 `A001-7` | 命中同一条冷板，而且**显示库存 100**（不再是缺货） |
| 选中 → 数量 `30` → 加入清单 | 清单里出现这一项 |
| 再搜 `A001-8` → 数量 `20` → 加入 | 清单 2 项 |
| 填领料人、用途 → 提交 | 提示成功 |

✅ **验证**：A001-7 库存 = 100 − 30 = **70**。

> ⚠️ 若 A001-8 没入过库，会弹「该物料缺货」加不进清单——**这是业务规则不是 bug**。
> 解决办法：回到第 1 步给 A001-8 也做一笔入库（数量填大些），再回来重试。

### 第 3 步：看流水对不对

首页 → **库存流水** → 应看到刚才那几条：入库 +100、出库 −30，
每条都带**单号**和**经手人**。

对着后台「单据管理」里的单号核一遍，两边要能对上。

### 第 4 步：盘点

| 操作 | 期望结果 |
|---|---|
| 首页 → **库存盘点** → 新建盘点任务 | 选仓库（配件仓）、选盘点范围 |
| 进任务 → 逐条填实际数量 | 账面数 = 第 2 步结束后的库存数 |
| 故意把某条填得比账面少 5 个 | 提交后显示**差异 −5** |
| 切仓管身份 → 待确认 → 确认 | 库存被调整为实际数 |

✅ **验证**：差异项确认后，库存 = 实际盘点数，流水里多一条盘点调整记录。

### 第 5 步：仓管确认 / 驳回

切 **开发·仓管** → 仓管工作台 → **待确认单据**

| 操作 | 期望结果 |
|---|---|
| 打开一张待确认单 | 能看到明细（物料、数量、单价、金额） |
| 点 **驳回** | **必须填驳回理由**，不填提交不了 |
| 驳回后切回出库员身份 → 首页 | 顶部出现红色提醒「你有 N 张出库单被驳回」 |

### 第 6 步：采购入库

切 **开发·采购** → **采购入库** → 搜料选中 → 填供应商 → 提交

回头用 **开发·入库** 身份看这张单能否正常确认、改价（详情页按料号改价会重算成本）。

### 第 7 步：老板看板

切 **开发·老板** → 数据看板 / 趋势分析 / 库存台账 / 库存预警。

> 注意一个已知的显示现象：库存长期不建账，1906 条里绝大部分是 0，预警页会标红一大片。
> 做过入库的那几条会从预警里消失——这正好用来验证预警逻辑是对的。

## 四、选料 / 搜索专项（逐条打勾）

选料是这个系统用得最多的动作，值得单独过一遍。

| # | 用例 | 怎么操作 | 期望 | 结果 |
|---|---|---|---|---|
| 1 | 输**完整编号** | 输 `A001-7` | **只出 1 条**，且是冷板 0.8\*1000\*1460 | ☐ |
| 2 | 输**大类前缀** | 输 `A001` | 出 50 条，全部属于「A001 板材型材」 | ☐ |
| 3 | 按**名称**模糊搜 | 输 `冷板` | 出多条，都含"冷板"二字 | ☐ |
| 4 | 搜**不存在的东西** | 输 `ZZZ-999` | 列表空，页面明确提示无数据，而不是一直转圈 | ☐ |
| 5 | 搜**别的仓**的料 | 出库员身份（只有配件仓）搜成品仓的料 | 查不到。这就是仓库隔离生效 | ☐ |
| 6 | 切换仓库再搜 | 顶部切到成品仓再搜 | 结果全是成品仓的，配件仓的不再出现 | ☐ |
| 7 | 连续加多条进清单 | 加 A001-7 → 再搜 A001-8 加进去 | 清单累计 2 项，数量互不覆盖 | ☐ |
| 8 | 重复加同一个 | 再选一次 A001-7 | 提示已在清单中，不会重复计 | ☐ |
| 9 | 缺货的料 | 选一个没入过库的编号 | 提示「该物料缺货」，加不进清单 | ☐ |

> 用例 1 有个历史坑：早期版本输 `A001-7` 会连带出来 `A001-10`~`A001-19`（模糊匹配命中前缀），
> 已修成「输入完整编号 = 精确匹配」。

## 五、验收标准（全打勾才算通过）

- ☐ 微信扫码能进小程序，进去就有数据（不是空列表）
- ☐ 搜索能出结果、能选中进料单
- ☐ 入库提交后库存**立刻**变化（不用等仓管确认）
- ☐ 出库时库存不足会被拦住，提示带了品名和单位
- ☐ 每条库存变动都能在流水里查到单号和经手人
- ☐ 仓管驳回必须填理由，驳回后出库员首页有提醒
- ☐ 出库员看不到别的仓的料（隔离生效）
- ☐ 盘点差异确认后，库存被调整成实际数
- ☐ 后台看到的数据和小程序完全一致

## 六、排错表

| 现象 | 大概率是什么 | 怎么确认 / 怎么修 |
|---|---|---|
| 页面能进、数据全空、一直转圈 | 用了「预览」而不是「真机调试」 | 改用真机调试；并确认 API_BASE 是局域网 IP |
| 连不上 / 请求超时 | Windows 防火墙拦了 3000 端口 | 本机 `curl http://192.168.10.7:3000/api/health` 通，多半是防火墙，放行 3000 入站 |
| 总之连不上 | 手机和电脑不在同一个 WiFi | 手机 ping 电脑 IP；换 WiFi 后 IP 会变，要重改 API_BASE |
| 搜 `A001-7` 出来十几条 | 编号被模糊匹配了 | 见第四节用例 1；若复现说明精确匹配逻辑被改回去了 |
| 什么都搜不到 | 关键词不对 | 先用手输 `A001-7` 验证链路，别急着怀疑网络 |
| 提示「该物料缺货」加不进清单 | 库存是 0 | 先做入库；这是业务规则不是 bug |
| 换身份后界面没变 | 身份没切成功 | 「我的」→ 开发身份，切完会重新登录，回首页看岗位入口 |
| 改了 API_BASE 没生效 | 没重新编译 | `npm run build:mp` 后开发者工具点「编译」 |

```bash
node -e "const n=require('os').networkInterfaces();Object.keys(n).forEach(k=>n[k].forEach(a=>{if(a.family==='IPv4'&&!a.internal)console.log(k+': '+a.address)}))"
```
