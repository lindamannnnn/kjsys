# 新旧系统对比分析报告

> 对比对象：现有 V3.1 统一入口版 vs 我们正在开发的微信小程序版
> 对比日期：2026-09-29

---

## 一、核心差异总览

| 维度 | V3.1 统一入口版（现有系统） | 我们开发的微信小程序版 | 差异说明 |
|------|---------------------------|----------------------|---------|
| **角色数量** | 4 个（领用员/采购员/仓管员/老板） | 3 个（车间/仓库/老板） | 我们少了「采购员」角色 |
| **入口方式** | 一张二维码，扫码后选身份 | 小程序码，进入后自动识别角色 | 他们是一张码多个身份，我们是多个小程序码 |
| **登录方式** | 工号 + 口令 | 微信授权登录 | 他们是账号密码，我们是微信一键登录 |
| **单据流程** | 提交 → 仓管确认 → 生效 | 提交 → 直接生效（或审批流） | 他们有仓管确认环节，我们简化了 |
| **权限控制** | 严格的角色隔离（领用员看不到成本） | 字段级权限（车间看不到成本价） | 权限设计一致 |
| **盘点功能** | 仓管盘点，立即生效 | 创建盘点任务 → 录入 → 审核 → 生效 | 我们多了审核环节 |
| **作废功能** | 仓管可作废单据 | 10 分钟内可撤销 | 他们更灵活，我们更简单 |
| **数据源** | 企业微信智能表格同步 | 全新开始，不迁移旧数据 | 他们有外部数据源，我们独立 |
| **部署方式** | 自建服务器（119.91.206.235:8899） | 微信云开发 | 他们是传统服务器，我们是 Serverless |

## 二、角色对比

| 角色 | V3.1 统一入口版 | 我们的版本 | 差异 |
|------|----------------|-----------|------|
| **领用员** | 领取物料，提交领料单（绿色） | 车间员工（out），领料出库 | 基本一致 |
| **采购员** | 购买物资，登记入库含单价（蓝色） | ❌ 无此角色 | **缺失** |
| **仓管员** | 确认出入库、作废错单、盘点（深绿） | 仓库管理员（in），入库登记、盘点 | 他们多了「确认/作废」权限 |
| **老板** | 全局查看，管理账号（金色） | 老板（boss），看板、用户管理 | 基本一致 |

## 七、建议

### 7.1 如果继续用现有 V3.1 系统

**优点**：
- 功能更完整（采购员角色、仓管确认、作废、批量操作）
- 已经在线上运行，有真实数据
- 员工已经熟悉

**缺点**：
- 自建服务器，运维成本高
- HTTP 明文传输，安全性差
- 口令制，无法追责到个人

### 7.2 如果切换到我们的微信小程序版

**优点**：
- 微信登录，更安全，可追责
- 云开发，免运维，自动备份
- 小程序原生体验

**缺点**：
- 功能不如 V3.1 完整（缺采购员、仓管确认、作废、批量操作）
- 需要重新培训员工
- 旧数据无法迁移

### 7.3 我的建议

| 场景 | 建议 |
|------|------|
| **短期（1-3 个月）** | 继续用 V3.1，同时开发我们的小程序版作为备选 |
| **中期（3-6 个月）** | 在我们的小程序版中补齐缺失功能（采购员、仓管确认、作废、批量操作） |
| **长期（6 个月以上）** | 完全切换到微信小程序版，淘汰 V3.1 |
