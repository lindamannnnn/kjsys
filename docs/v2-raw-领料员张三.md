## 后台与小程序一致性

### A. 后台出库单页面「有没有」V2 的新状态与新按钮？——有

读 `admin/src/views/order/outbound.vue`：
- 状态筛选完整包含 4 态：`待确认 / 待拣货 / 待收货 / 已完成`（另含 已驳回 / 已作废），见 `outbound.vue:9-17`
- 操作按钮随状态联动：`pending`→「确认」、`picking`→「拣货完成」、`receiving`→「代确认收货」，见 `outbound.vue:78-101`

### B. 后台「有没有消息中心」？——**没有页面，只有接口封装**

### C. 后台首页（数据看板）「有没有」V2 的待办计数？——**没有**

`admin/src/views/dashboard.vue:30-41` 的"待办"只统计了 **`待确认出库单` / `待确认入库单` / `待审核用户` / `进行中盘点`**：

## 严重问题汇总

### P0 致命（不修我没法用）
**本轮未发现。** 出库四阶段流程完整、库存扣减时机正确、异常输入全部被拦、越权全部被 403 拦住、自己的单据和库存对得上账。没有出现"数据会错 / 越权 / 流程断掉"级别的问题。

### P1 严重（很影响效率）
1. **消息中心对所有测试账号完全失效，且系统谎报"已通知领料员"**（P1-1 / 3-1 相关）
   - 证据：`pickDone{584}` → `"拣货完成，已通知领料员来收货"`；随即 `message.list` → `{"list":[],"total":0,"unread":0}`；赵六、李娜、管理员的消息中心同样全空（`total:0`）。
   - 根因（读码定位）：`server/src/modules/message.js:13-15` 取 `ctx.user.openid`，而账号密码登录的用户 `openid` 为空串，`list` 直接返回空；`server/src/services/message.js:30-48/109` 投递时按 `openid` 过滤，无 openid 的账号**既发不出也收不到**。小程序 `pages/out/detail.vue:57` 还写着"拣完会给你发消息"，承诺落空。
   - 影响：V2 的核心新增功能（P1 消息中心）在实测中 **100% 不可用**；这正是我最怕的"点了没反应"。补救入口仅剩首页 `myNotice` 蓝卡片。
   - 标注（推测）：真实微信登录用户若带 openid 应该能收到；当前 4 个测试账号都是用户名/密码登录、openid 为空，因此全部收不到。
2. **领料员能提交「报废 / 销售」等非领用类型出库单**（3-1）
   - 证据：`submit{type:"baofei"}`、`submit{type:"xiaoshou"}` 均 `code:0` 且生成单号。
   - 影响：与手册"领料员默认只做领用"不符，存在把料以销售/报废名义开单的合规与防呆隐患。
3. **领料员在 picking/receiving 时撤不了自己的单，且与手册描述矛盾**（2-2）
   - 证据：手册写"`pending/picking/receiving` 谁都能撤"；实测 `cancel{id:590}` → `403 该单据已由仓管受理`。
   - 影响：填错数量后只能找仓管，多绕路；照手册操作会碰壁。
4. **后台首页看不到「待拣货 / 待收货」积压**（C-1）
   - 证据：`dashboard.vue:30-41` 仅"待确认出库单"，无待拣货/待收货计数；小程序仓管工作台反而已有。

### P2 体验（能用但别扭）
1. 数量校验报错显示编号「2100」而非物料名（2-1）
2. 领料员撤单可不填原因（2-3）
3. 领料员能看到全仓库存金额 `total_value`（3-3）
4. `pendingCount`/`pickingCount` 对领料员返回全仓计数，与本人无关（3-4）
5. 同一单可重复添加同一物料产生两行，无合并/提示（3-5）
6. 后台缺消息中心页面（有 API 无页面）（B-1）
7. 接口手册字段名与实际不符：手册写 `unreadOnly`，实际代码读的是 `only_unread`（`message.js:22-26`，小程序 `pages/message/list.vue:89` 用的也是 `only_unread`）——照手册传 `unreadOnly` 会被忽略

## 我这个岗位愿不愿意继续用？为什么？

**愿意用，但有个大前提：得先把「消息」这条线弄明白。**

平心而论，这版比老版本让我踏实：我在手机上点「确认收货」之前，库存不会被提前扣走，跟我"走到仓库拿到货才算数"的习惯完全一致；数量填错、料不存在、库存不够，系统都拦得干干净净，还告诉我差多少、该怎么办——这些都说人话，我一个不太会用电脑的人也看得懂。

但**「消息中心永远空」这件事真的膈应人**。小程序首页挂着铃铛、详情页写着"拣完会给你发消息"，我点进去却啥也没有——我最怕的"点了没反应"就长这样。我现在只能靠每次回到首页看有没有蓝卡片来判断"该不该去收货"，等于把新做的通知功能当空气。

所以：**消息修好、领料员别再能开销售/报废单，我就踏实天天用；这两个不改，我就还得多留个心眼，每次自己盯着首页和库存数字。**
