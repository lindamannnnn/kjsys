# 【采购员】李娜 · 3 轮真实使用汇报

## 使用前提

我是李娜，配件仓采购员（账号 `lina`，角色 `purchase`，可管仓库 1=配件仓）。
每天的工作：给供应商下单，货到做采购入库、录单价，月底拿单据跟供应商对账。
我一次要录十几项，坐在电脑前敲数字，对单价/金额/加权成本很敏感。
我最在意两件事：**单价录错了要能改，改完账要对得上**；**别让我每次重新录一遍单价**。

本轮只操作 6 个【测试】物料（临时供应商 1 个），未触碰 1909 条真实物料。
测试期间发现别的同事（张三、赵六、王总）也在同时操作（出库、确认、盘点），
凡状态与预期不符的我都先回查确认，未当 bug 报。

## 第 2 轮：改价与对账（重点，问题最严重）

### 操作过程

**1）发现 D 型单价录错，想从 9.9 改成 10.5**

先按手册（第六节/三节）给的格式 `items[]` 改：
```
POST /api/inbound {"action":"updatePrice","data":{"id":23,"items":[{"material_id":1915,"unit_price":10.5}]}}
→ {"code":400,"data":null,"message":"单价无效"}
```
手册说的格式**根本用不了（报"单价无效"）**。再试界面 `detail.vue` 实际发送的扁平格式：
```
POST /api/inbound {"action":"updatePrice","data":{"id":23,"unit_price":10.5}}
→ {"code":500,"data":null,"message":"total is not defined"}
```
**报 500 说失败。但我回查单据，数据已经被改了，而且改坏了：**
```
POST /api/inbound {"action":"detail","data":{"id":23}}
→ {"order_no":"IN-20260929-003","total_price":3675, "items":[
     {"material_id":1915,"unit_price":10.5,"total_price":2100},
     {"material_id":1916,"unit_price":10.5,"total_price":1575}]}
```
> 我**只要求改 D 型**，结果 **E 型也被从 15 改成 10.5**（150×10.5=1575）。
> 一张 2 项的单，改一个物料把整单所有单价都覆盖成了同一个价。

**2）改价后成本有没有跟着重算？**
```
D 型 avg_cost 仍为 9.9（单据显示 10.5）
```
**没有重算。**单据金额变了、库存账面成本没变 → 账立刻对不上。

**3）用一张干净的单据隔离复现（排除并发干扰）**
先建单项单：E 型 数量10 单价8 → `IN-20260929-004(id=24)`，成本变 14.5625（= (150×15+10×8)/160 ✔）。
再改这张单项单：
```
POST /api/inbound {"action":"updatePrice","data":{"id":24,"unit_price":7}}
→ {"code":500,"data":null,"message":"total is not defined"}
回查 id=24 → unit_price:7, total_price:70   ← 报错但仍改了
回查 E 型 → avg_cost:14.5625（未重算，正确应为 (150×15+10×7)/160=14.1875）
```
隔离复现成功：**报 500 = 假失败，数据实际已改，成本不重算**。

**4）改别人的 / 已确认的单据**
```
改已确认的 IN-20260929-001(id=21)：{"code":400,"message":"单据已确认，不能修改单价"}
改赵六提交的单(id=25)：      {"code":403,"message":"只能修改自己提交的单据"}  ✔（权限正确）
```

**5）加权平均是否算对（再入一批 D 型 100 个 @11）**
```
POST /api/inbound client_request_id="lina-r2-batch" → IN-20260929-006, 100×11=1100 ✔
回查 D 型 → current_stock:300, avg_cost:10.2667
```
系统算的：`(200×9.9 + 100×11)/300 = 3080/300 = 10.2667` —— **公式本身是对的**，但它用的是**没被改价的旧成本 9.9**。
如果第 1 步改价正确生效（D 应按 10.5 计），应是 `(200×10.5+100×11)/300 = 3200/300 = 10.6667`。
> **我算的：10.6667；系统给的：10.2667。单价差 0.4 元/个 × 300 个 = 库存账面少计 120 元。**

**6）"更早的单据"**
仓库里现有单据的创建时间都是今天（2026-09-29），`IN-20260929-001` 是被仓管确认过的，所以拒改原因是**"已确认"**而不是"非当天"。
非当天不可改这条我看不到直接证据，仅从后端代码 `inbound.js:287-289`（"非当天且非老板 → 400"）判断，标为**推测**。

### 遇到的问题

| 序 | 问题 | 严重度 | 证据（请求→响应） | 为什么干不下去 |
|---|---|---|---|---|
| 3 | 改价接口**报 500 但数据已改**（报错与落库不一致） | P0 | `{"action":"updatePrice","data":{"id":24,"unit_price":7}}` → `{"code":500,"message":"total is not defined"}`；随后回查 id=24 `unit_price:7,total_price:70` | 员工看到"失败"会以为没改成，反复点、或改用别的办法再录一遍 → 单价/金额被反复改乱，根本不知道当前是几 |
| 4 | 改价**不重算加权成本**，单据与账面对不上 | P0 | 单据 D 项 10.5，D 型 `avg_cost` 仍 9.9；再入 100@11 后系统 10.2667 vs 正确 10.6667 | 这是我最恨的"账面库存金额和实际对不上"。改完价，单据改了、账没改，月底对账永远差 120 元 |
| 5 | 改价**忽略 material_id，覆盖整单所有明细** | P0 | 改 D（1915）→ 回查 id=23 两项都变成 `unit_price:10.5`（E 型 15→10.5） | 我改一个料号，把同单另外几个料号的价格一起改了，金额全错，且没有任何提示 |
| 6 | 界面上**根本没有可用的改价入口** | P0 | `detail.vue:78-85` 按钮条件要求"待确认+本人+当天+**单项**"，且比对 `order.operator_openid === userStore.openid`；实际单据 `operator_openid:"lina"` 而 `getUserInfo.openid:null` → 永不相等；且它发送的 `{id, unit_price}` 正是上面 500 的路径 | 我一次录十几项（多项目单据），按界面规则**永远看不到改价按钮**；就算单项单，按钮也不显示；万一显示了，点了就 500 还把账改乱。**"录错了要能改"这个最基本的要求做不到** |
| 7 | 已确认单据采购员无法纠正 | P1 | 改 id=21 → `{"code":400,"message":"单据已确认，不能修改单价"}` | 仓管一旦确认，我录错价就永久锁死，只能求管理员；月底发现错价时单据早被确认了 |

### 本轮结论

**这轮基本干不下去。** 核心诉求是"单价错了能改、改完账对得上"，而系统是：
- 按手册的格式改 → 报"单价无效"；
- 按界面的格式改 → 报 500（但偷偷把账改了，还连累同单其它物料）；
- 改完成本不重算 → 账面金额和单据差 120 元。
改价这条路是**堵死的、而且是会搞坏数据的**。

批量 12 项**无限制、0.45 秒、单号只生成一个**，效率没问题。

```
重复发送 client_request_id="lina-r3-batch12"
```

**4）我提交盘点后，库存有没有被改？（实测）**
```
提交前 D 型 current_stock:302 / E 型 current_stock:162
POST /api/check {"action":"submit","data":{"id":12,"items":[{"material_id":1915,"actual_stock":302},{"material_id":1916,"actual_stock":162}]}}
→ {"code":0,"message":"盘点结果已提交，等待审核"}
提交后 D 型 current_stock:302 / E 型 current_stock:162   ← 未变
盘点单 id=12 状态 → pending_review
```
> 任务里"盘点是能直接改库存的"这个前提，实测**不成立**：`submit` 只写盘点明细、把状态改成待审核，**不动库存**；
> 真正回写库存的是老板的 `review`（`check.js:282-299`，只有 `is_checked=1` 的差异项会被调整）。
> 所以我能"越权提交盘点"是真的（采购员不该录盘点），但**没有直接把库存改坏**。
> 我用的是"实际数=当前账面数"（差异为 0）来验证，避免影响真实物料。

**5）对账：入库 − 出库 = 当前库存？**

我想用 `stats/stockFlow`（库存变动流水）拉 D 型的流水，但它不给我看：
```
POST /api/stats {"action":"stockFlow","data":{"material_id":1915}}

```
只能退而用我有权限的入库单列表自己加：
```
D 型(1915) 全部入库明细：
  IN-20260929-007  +1
  IN-20260929-007  +1
  IN-20260929-006  +100
  IN-20260929-003  +200
  合计入库 = 302，出库 = 0，当前库存 = 302   ✔ 恒等式成立
```
另：`stats/stockList` 我能看，D 型 `stock_value:3082.0006`（=302×10.2053 ✔ 金额算得对）；
`stats/warning` 也能看（预警清单，只读）。

### 遇到的问题

| 序 | 问题 | 严重度 | 证据（请求→响应） | 为什么干不下去 |
|---|---|---|---|---|
| 8 | 采购员无权限查**库存变动流水**（stockFlow），对账难 | P1 | `{"action":"stockFlow","data":{"material_id":1915}}` → `{"code":403,"message":"无操作权限"}` | 你让我核对"入库−出库=库存"，我拿不到流水，只能把入库单列表翻出来手加；出库单我也看不到（outbound/list 对我返回空 `{"list":[],"total":0}`）。月底对账全靠手工，这正是我的痛点 |
| 9 | 采购员能提交**盘点结果**（越权录入） | P1 | `check/submit` id=12 → `{"code":0,"message":"盘点结果已提交，等待审核"}`（且对不存在的 id 返回 404 而非 403，说明该动作没做角色校验） | 盘点归仓管，采购员不该能录盘点数。虽然不动库存，但我能把盘点数据填成任意值推进到"待审核"，若老板照批，账就被改了 |

### 本轮结论

**批量录入与防重复提交这两块是合格的**（12 项 0.45 秒、单号唯一、幂等提示清楚）。
**越权控制整体到位**（confirm / reject / 各类 stats / user / material / check.create / check.review 全部 403），只有 `check/submit` 漏了。
**对账能力不足**：采购员看不到库存流水和出库单，"入库−出库=库存"只能靠自己拿入库单加，效率低、易漏。

## 严重问题汇总

### P0 致命（不修我没法用）

1. **改价接口报 500 但数据已改**（假失败真落库）。
   证据：`{"action":"updatePrice","data":{"id":24,"unit_price":7}}` → `{"code":500,"message":"total is not defined"}`；回查 id=24 `unit_price:7,total_price:70`。
   影响：员工以为没改成 → 反复操作 / 换方式重录，单价与金额被改乱且无从确认当前值。

2. **改价后库存加权成本不重算，单据与账面对不上**。
   证据：单据 D 项已改 10.5，D 型 `avg_cost` 仍 9.9；再入 100@11 后系统 `10.2667`，正确应为 `10.6667`。
   我算的数：**10.6667**；系统给：**10.2667**；差异 0.4×300 = **库存账面少计 120 元**。

3. **改价忽略 material_id，把整单所有明细覆盖成同一个单价**。
   证据：只改 D(1915) → 回查 id=23 两项均 `unit_price:10.5`（E 型 15→10.5，金额 2250→1575）。
   影响：改一个料号连累整单金额，采购对账必错。

4. **界面上没有可用、正确的改价入口**（流程断掉）。
   证据：`detail.vue:78-85` 要求"待确认+本人+当天+**单项**"，且用 `order.operator_openid("lina") === userStore.openid(null)` 判断→永不相等；其调用的参数 `{id, unit_price}` 正是上面的 500 路径。
   影响：我一次录十几项，"单价录错了要能改"这件事在界面上根本做不到。

### P1 严重（很影响效率）

5. **供应商税号 `tax_no`、账期 `payment_term` 被静默丢弃**。传了返回成功，list/detail 都查不到 → 对账开票、排付款计划做不了。

6. **已确认单据采购员无法纠错**。`{"code":400,"message":"单据已确认，不能修改单价"}` → 录错价被确认后永久锁死。

7. **采购员查不到库存变动流水 `stats/stockFlow`**（403），也看不到出库单（outbound/list 返回空）→ 月底对账只能手工加入库单，效率低、易漏。

8. **采购员能提交盘点结果 `check/submit`**（无角色校验，404 而非 403）→ 越权录入盘点数据。

### P2 体验（能用但别扭）

9. 入库单**历史列表不显示单价**（只显示总金额 `total_price`），对账要逐单点开看。
10. 供应商 `search` 接口只按名称匹配，按联系人/电话/税号搜不到；界面弹窗承诺"名称/联系人"（好在 UI 走的是 list，list 能按联系人/电话匹配，影响被掩盖）。
11. 供应商选择弹窗只显示 名称/联系人/电话/地址，不显示税号/账期（因为这两个字段压根没存）。

## 我这个岗位愿不愿意继续用？为什么？

**现在的版本：不愿意用。**

原因很直接——我来这里就是为了把"进货、录价、对账"这条线走顺，而它恰好在这条线上是坏的：

- 我的头号诉求是"**单价录错了要能改，改完账要对得上**"。可这个系统：按手册格式改报"单价无效"；按界面格式改报 500 却**偷偷把账改了，还把我同单其它物料的价格一起改掉**；改完**库存成本根本不跟着变**。我自己算的账和系统给的账差 120 元，而且我**不知道到底改没改成功**。这在采购岗是致命的——账面库存金额和实际对不上，月底跟供应商对账就是对不上，我要挨批。
- 我的第二大诉求是"**供应商信息要全**"。结果税号、账期录进去就没了，供应商档案是残废的。
- 对账时我又看不到库存流水和出库单，只能手工把入库单加一遍。

**但也有好的地方，值得说清楚**：
- 一次提交十几项很顺（12 项 0.45 秒、单号唯一），防重复提交做得对且提示清楚；
- 权限控制整体靠谱，我想越权看趋势/操作员统计/用户管理/建料号，全被 403 挡住了；
- 加权平均的**公式本身是对的**，错的只是"改价后不去重算"这一步；
- 报错提示大多说人话（"只能修改自己提交的单据""请勿重复操作"我能看懂）。

**结论**：只要把"改价"这一件事修对（① 返回真实成功/失败，不要 500 假失败；② 按 material_id 精确改指定明细，别覆盖整单；③ 改完同步重算该物料加权成本；④ 界面上给采购员一个能用的改价入口，别限制"单项"），再补上供应商税号/账期的落库和对账用的库存流水权限，**我愿意用**——因为它的批量录入和权限底子是好的。但在这之前，我不敢用它管我的采购账。
