## 一之二、本批修复：连点两下出两张单（P1）

**现象**：出库页快速连点两次「提交」，会产生两张一模一样的出库单，**库存扣两遍**。
网络超时后用户手动重试，同样出双单。

**根因有两层，缺一层都堵不住**：

1. **前端幂等键形同虚设**（主因）：`utils/cloud.js` 每次请求都现生成一个
   `client_request_id` —— 等于每次都告诉后端「这是新的一笔」，**后端的幂等机制完全失效**。
2. **提交过程没有闩锁**：`showLoading` 没加 `mask`，遮罩挡不住点击，也没有防重复提交的状态位。

**改法**：

| 位置 | 改动 |
|---|---|
| `utils/cloud.js` | 幂等键按「模块+动作+参数」指纹**复用**：结果未知（网络异常/超时）时保留、重试复用；确定成功或确定失败才作废 |
| 4 个提交页（出库/入库/采购/盘点） | 加 `submitting` 闩锁 + `showLoading({ mask: true })`，用 `finally` 保证复位 |
| 另外 4 处 loading（改价、审核、登录、改资料） | 一并补上 `mask: true` |
| `server/src/modules/inbound.js` | 采购入库**供应商必填**兜底（前端置灰按钮只是提醒，后端才拦得住直接调接口） |

**关键设计**：参数完全相同的两次提交共用一个键（连点、超时重试都不会变成两笔），
但**成功之后立即作废** —— 用户真心想连下两笔时照常出两张单，不会误伤。

**证据**（`server/tests/duplicate-submit-test.js`，35 项）：

- 前端机制 7 项：复用键 / 网络异常后复用 / 成功后换新键 / 业务失败后换新键 / 参数不同不共用 / 键序无关 / 重复标记可识别
- 后端兜底：同一幂等键**并发 3 次** → 库里只有 **1 张单**、库存只扣 1 次、其中 2 次被标记为重复
- **防误伤**：不同幂等键的连续两笔 → 照常出 **2 张单**、库存扣 2 次
- **端到端对照实验**：同一套用例只换前端实现 ——
  **修复前 2 张单 / 扣 4 件，修复后 1 张单 / 扣 2 件**
  （修复前那版代码已固化在 `tests/fixtures/cloud-before-dedup-fix.js`，以后谁改回去对照实验会立刻报警）

**未做（如实记录）**：`supplier_id` 的存在性校验还没加 —— 传一个不存在的供应商 id 仍会被存下。

## 二、提交审核前必须解决（2 项，都需要你操作）

### 1. ★ 接口地址是 `http://119.91.206.235:3000` —— 这是最大的阻塞

**问题**：微信小程序**正式版只允许 https + 已备案域名**，不允许 http，也不允许直接用 IP。

**后果分两种情况**：
- 体验版 / 开发者工具：勾选「不校验合法域名」就能正常用（给老板演示够用）
- **提交审核后：审核员打开小程序，请求会被直接拦断**
  → 审核员看到的是空白或登录不了 → **大概率以「功能无法使用」被拒**

**解决办法**（按顺序）：
1. 买一个域名（几十元/年）
2. 域名做 **ICP 备案**（通常 1~3 周，腾讯云控制台可提）
3. 备案通过后申请免费 SSL 证书，服务器配 HTTPS
4. 小程序 `src/utils/cloud.js` 的 `API_BASE` 换成 `https://你的域名`
5. 微信后台把域名加入「服务器域名」白名单

**过渡建议**：备案期间先用**体验版**给老板看演示效果（体验版最多 15 人），
等 HTTPS 和域名都就绪了再提交审核，避免白提交一次留下驳回记录。
