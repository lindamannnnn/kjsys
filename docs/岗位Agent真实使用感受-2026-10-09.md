# 6 岗位 Agent 真实使用感受（2026-10-09 复测）

> **这次测了什么**：让 6 个岗位「以真实使用者身份」各跑 3 轮完整业务闭环，共 **783 条断言**；
> 再用真实浏览器做 **23 条体感复验**，专查「点了到底有没有反应」。
> 本文讲的是**用起来的感受**，不是接口流水。每条感受都带断言数或浏览器实测证据。
>
> ⚠️ **口径**：接口层是真实调用；浏览器层跑的是 H5 产物（只作交互逻辑证据），
> 真机手感 / 滚动流畅度需在微信开发者工具或真机补验，本文不臆断。

---

## 一句话结论

**系统现在是「稳」的——不该让你干的事，它真的拦得住；你犯的错，它接得住。**
783 条断言零失败、23 条体感复验零失败。上一轮被吐槽的「假按钮、点了没反应」这轮**全部变成真的了**。

但还有一处**结构性别扭**没解决：**提醒到不了人**。消息没有稳定入口（底部只有「首页/我的」），
被驳回、待收货、待审核仍然要用户自己回首页看。按你的决定，这条**后续走企业微信**，本轮未动。

## 一、六个岗位的真实感受

按「活有多重」排序（断言数 = 这个岗位在一轮里被验证了多少件事）。

### 1. 仓管 —— 「全系统的枢纽，也是最累的一个」

**231 条断言（占全量 29%，六个岗位里最重）**

**我干了什么**：建档 → 入库（单价 0 / 负数要被拦）→ 出库确认 → 拣货 → 收货 → 建采购任务 → 采购收料 → 盘点建单/录入/提交 → 越权探针。

**真实感受**：
- **活是真多**。入库、出库、盘点、采购四条线仓管都要碰，等于所有单据都从他手上过。231 条断言就是证据——比采购员多了近 3 倍。
- **好在「拦得住」**：单价填 0、填负数，都被明确拒绝；**待审的盘点单想再改数也会被拒**（防偷改，这条很关键）。
- **会手抖的地方**：误操作包里专门测了「重复拣货」——说明连点两下确实会发生。系统返回的是**幂等提示**（不出错、不重复扣库存），这个处理是对的。

### 2. 老板 —— 「我什么都看得到，但什么都干不了」（这是设计）

**141 条断言**

**我干了什么**：试图审核盘点（被拒）、试图驳回出库（被拒）、查消息（确认不再收到待审通知）、看板取数。

**真实感受**：
- 141 条里有**一大半是「我想干但被拒绝」**——这不是 bug，是 2026-10-09 定的「老板只读」。
- **最让人放心的一条**：被拒之后，**库存确实没变**。不是「提示失败但其实改了」那种假拒绝——测试专门比对了驳回前后的库存数字。
- **待审通知不再发给老板了**（审核已归厂长 + 管理员），收件箱干净了。

### 3. 领料员 —— 「撤销规则很清楚，但有一处反馈是延迟的」

**138 条断言**

**我干了什么**：提交领料单（wh2 的物料会被拒）→ 撤销规则探针 → 确认收货 → 收消息 → 越权探针。

**真实感受**：
- **撤销规则讲得很清楚**：待确认可撤、待拣货可撤、待收货**不可撤**（必须走收货完成）。而且**2 小时前的老单照样能撤**——不限时，这点很人性化。
- **跨仓拿料直接拒**：我是 wh1 的人，wh2 的物料提都不让提。
- ⚠️ **唯一别扭的地方**：**超额领料提交时不拦**。因为我（领料员）看不见库存，系统让我提交成功，等仓管确认时才以「库存不足」拒掉。
  体感上是「我提交成功了 → 过一会儿才知道白干」。这是设计取舍（缺货由仓管把关），但**反馈是延迟的**。

### 4. 管理员 —— 「唯一管理员不能被降级，这条保住了」

**129 条断言**

**我干了什么**：后台登录 → 看板取数 → 盘点审核（**正例**，老板被拒的那条这里能过）→ 查消息 → 预警口径一致性 → 唯一管理员保护 → 用户管理。

**真实感受**：
- **唯一管理员不可被降级**——否则系统会变成「没人能管」，这条是 P0 级的保险。
- **老板看板和我看的后台看板数字一致**、**预警四个口径一致**。两端对得上，数字才敢信。

### 5. 采购员 —— 「流程最短，最轻松」

**81 条断言**

**我干了什么**：领任务 → 录单价 / 备注 → 越权探针。

**真实感受**：
- **最轻松的正式岗位**，81 条断言只有仓管的三分之一。
- **重复领取任务是「幂等提示」不是报错**（还是自己的任务、不会易主）——这个设计对。

### 6. 厂长 —— 「边界最清楚的一个岗位」

**54 条断言**

**我干了什么**：建档 → 看两个仓库的库存（**含金额**）→ 盘点全流程 → 发采购单 → 点开别人建的盘点单。

**真实感受**：
- **该干的都通**：盘点、发采购单、看两仓库存含金额。
- **不该干的全被拒**：入库、驳回出库、删物料、建用户、看趋势分析——5 条越权全拦。
- **最关键的一条**：**能点开别人（仓管）建的盘点单**。这条通了，审核入口才真的可达——否则权限给了也是废的。

### 附：匿名访客 —— 9 条

未登录 401、伪造 token 401、乱写模块名被拒。**门是关着的。**

## 二、人真的会犯的错，系统接得住吗

误操作包专门模拟「手滑」，这是最能体现「好不好用」的部分：

| 我会犯的错 | 系统的反应 | 感受 |
|---|---|---|
| 网络卡了**连点两下提交** | 只落**一张单**，第二次返回「已提交过」 | 👍 最怕的重复单没有发生 |
| 数量填 0 / -1 / 1.5 / 文字 | 全部明确拒绝 | 👍 说得清 |
| 查**不存在**的物料 | 明确 404 | 👍 不是静默 |
| 报废单**忘传照片 / 忘写备注** | 被拒 | ⚠️ 业务规则，容易漏（但有提示） |
| **改价填 0** | 被拒 | 👍 成本不会失真 |
| **档案里直接改库存** | 被拒（P0） | 👍 这个口子必须封死 |
| **超额领料** | 提交时不拦，仓管确认时才拒 | ⚠️ 见上文「反馈延迟」 |
| 重复收货 / 重复拣货 / 重复领取 | 幂等提示，不重复扣 | 👍 手抖安全 |

## 三、上一轮修的东西，现在真的好用了吗

这是本轮新增的**体感复验**（真实浏览器，23 条全绿）。上一轮报告吐槽最多的是「点了没反应」，这次逐条复验：

### ✅ 看板「今天 / 本周 / 本月」—— 真的会重新取数了（10 条）

| 验证 | 结果 |
|---|---|
| 点「本周」真的重新发了请求 | ✅ |
| 请求**真的带 `period=week`**、本月带 `month`、今天带 `today` | ✅ 三个都对 |
| 切完 **KPI 标题跟着变**（显示「本周出库单数」而不只是数字变） | ✅ |

**感受**：以前点这三个 tab，数字纹丝不动（前端只改了个变量）。现在**每点一次就发一次带周期的请求**，连标题都跟着改。这条修得很彻底。

### ✅ 预警页「通知采购」—— 不再是假按钮（4 条）

| 验证 | 结果 |
|---|---|
| 点下去**真的调了 `notifyWarning` 接口** | ✅ |
| 通知**带上具体物料**（不是整批乱发） | ✅ |
| **页面给了可见反馈**（弹 toast「已通知 N 人」） | ✅ |

**感受**：原来这个按钮只有一句 toast、零接口调用——**老板会真以为采购已经收到通知了**，漏补货是业务损失。现在通知真的落到采购员和仓管的收件箱里。

### ✅ 搜索防抖 —— 连敲 6 个字只发 ≤3 次请求（2 条）

近 2000 条物料下，以前每敲一个字发一次请求会卡。现在防抖生效（实测 ≤3 次），且**确实发起了搜索**（不是没反应）。

### ✅ 上拉加载 —— 真的能加载第二页（3 条）

**实测造了 25 条任务**（每页 20 条），滚到底 → **真的发出了 `page=2` 的请求**，任务行正常渲染。
以前这些列表固定 50/100 条、翻不到也搜不到，现在能翻了。

### ✅ 「修改密码」入口 —— 真的存在且点得进去（3 条）

「我的」页有入口 → 点得进去 → 表单正常渲染。
这条原来是个 **P0**：后端有「首次登录强制改密」门禁，但小程序端没有改密页——**命中即锁死**（账号被后台重置过密码后再用小程序登录就进不去了）。

## 六、这次踩到的三个坑（都修了，写在这是为了别再犯）

1. **脚本崩溃污染了基线**：造测试数据的 `UPDATE` 写在 `try` 之前，下一句字段名写错崩了 → `finally` 没执行 →
   一个真实物料被永久改成「库存 0 / 预警值 5」，还得翻备份表找回原值。
   **已修**：造数据的 SQL 一律放进 `try` 里；还原时 `current_stock` 和 `warning_stock` **都要**还原。
2. **toast 采样时机导致误判**：先 `sleep(2000)` 等请求再抓文案，而 toast 只显示 1.5 秒 → 采了个空，
   误判成「点了没反馈」。**已修**：改成边等边高频采样。
3. **判据用错了字段**：拿任务列表去匹配 `remark`，而列表卡片显示的是**任务号 + 状态**，根本不显示 remark → 恒假。
   **已修**：判据换成列表上真实可见的东西。
