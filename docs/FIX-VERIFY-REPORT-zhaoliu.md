## 仍存在的问题（非本次 5 项修复范围）

1. **数据只在内存，刷新页面即丢失**：所有库存变动直接改 `mockData.js` 导出的数组，没有持久化。真机上关掉小程序再打开，确认/作废/盘点全白做。**这是当前最大风险**——我这个仓管最怕的就是"我以为改了，其实没改"。
2. **确认/作废没有写库存流水**：pending.vue 和 orders.vue 的确认、作废只改了 `current_stock` 数字，没有像盘点那样调 `addStockLog`。追责链还是断的——老板问"这 2 支减震器谁动的"，流水里查不到。
3. **盘点没锁库存**：`freeze_stock: true` 字段还在睡大觉，盘点期间别人照样能确认出入库单，盘完数又对不上（老问题 P1#9 仍在）。
4. **待确认列表的作废按钮逻辑有歧义**：pending.vue 里待确认单据点「作废」也做库存回算（195-198 行），但待确认的单据库存本来就没动过，回算是多此一举——好在数字上加减抵消不会错，但逻辑上应该只改状态不回算。
5. **无审核环节**：盘点提交后状态直接变 pending_review，但系统里没有"审核通过/驳回"的入口（那是老板的活），如果老板那边没做审核按钮，盘点单会一直挂着。

## 整体评价

**上次我说"现在这版，我不敢用"。这次修完，我改口：核心的库存数字能信了，但还不能真上岗。**

**好的方面**：
- 上次最要命的三个问题——确认不动库存、作废逻辑反了、确认后没法作废——全修好了，我亲手点了一遍，数字分毫不差
- 确认前能看到库存够不够，不够直接拦住不让点，这个对我们仓管太重要了，出了错是我的责任
- 盘点提交后状态真的变了，库存按实盘数走，流水也有记录

**还不敢用的原因**：
- 数据不落库，心里没底（问题 1）
- 确认/作废不留痕，出了事说不清（问题 2）

**一句话**：从"不敢用"进步到"演示能用"，把数据持久化和操作留痕补上，我就敢把本子扔了。
